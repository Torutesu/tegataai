## 3. 事業内容（指定役務の設計に必要な情報）

AI ソフトウェア事業者向けの **SaaS（クラウド提供のソフトウェア）** です。具体的には:

1. **利用権（クレジット）の残高管理と、処理実行前の可否判定**
   顧客のアプリケーションが AI 処理を実行する直前に API を呼び出し、
   残高・上限・ポリシーに照らして「実行してよいか」を返す
2. **原価計算とマージンの可視化**（ダッシュボード）
3. **監査ログの提供**（追記専用の記録と、その検証ツール）
4. 上記に関する**ソフトウェア（SDK）の提供**、および仕様の公開

**重要（規制上の位置づけ）**:
当社は**資金の保管・移動・決済処理を行いません**。決済は既存の決済代行事業者
（Stripe 等）が行い、当社はその上に載る「実行してよいかの判定と記録」に徹します。
指定役務の設計にあたっては、**金融・決済サービスそのものと誤認されない**
区分・記載としていただきたく存じます。

**想定区分（ご助言をいただきたい前提としての当方の素案）**
- 第9類: ダウンロード可能なコンピュータソフトウェア
- 第42類: SaaS、クラウドコンピューティング、ソフトウェアの設計・開発
- 第36類の要否: **当方は不要と考えているが、判断を仰ぎたい**
  （決済に「隣接」するが、資金移動も決済処理も行わないため）

## 4. 特に確認したい論点

### 4-1. 日本における「手形」の識別力（最重要）

「手形」は日本語の**一般名詞**（bill of exchange / promissory note）であり、
商業上の一般用語です。以下を確認したく存じます。

- 欧文表記「TEGATA」が、第9類・第42類において**識別力を有するか**
- 一般名詞の音写であることが、拒絶理由（商標法3条1項3号等）となる可能性
- 図形商標（§2 の割印マーク）との**結合商標**とすることで識別力を補強できるか、
  あるいは図形のみを別途出願すべきか

**既知の懸念**: Oracle NetSuite の日本版が機能名として "tegata" を使用していると
認識しています（当方未確認）。この種の記述的使用が識別力判断に与える影響についても
ご教示ください。

### 4-2. 既存の類似商標との抵触

- 日本・米国において、**第9類・第36類・第42類**で "TEGATA" と類似する先行商標がないか
- 特に**決済・フィンテック分野**の登録商標との抵触
- 称呼（テガタ / TEGATA）が近い商標（例: TEGATA / TEGRA / TAGATA 等）の有無

### 4-3. 過去の教訓を踏まえた確認

決済分野では、同種の音の名称が既に大手の合弁事業で使用されている例があります
（PAYGENT / 株式会社ペイジェント、加盟店規模 約1.3万店）。
**着手後に判明して名称変更を余儀なくされる事態を最も避けたい**ため、
「登録可能性」だけでなく、**未登録の周知・著名標章との抵触リスク**についても
併せてご確認いただけますと幸いです。

### 4-4. 米国出願

- 使用主義の下、**ITU（使用意思に基づく出願）**での先行出願の要否と時期
- 日本出願を基礎としたマドプロ出願と、米国直接出願の比較（費用・期間・確実性）
