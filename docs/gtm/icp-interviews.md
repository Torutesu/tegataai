# ICP ヒアリング設計

Select KK / 2026-08-21 / v0.1
目的: Master Doc §6.1 の GTM Prototype gate 判定材料を得る。

> **このドキュメントの位置づけ**: ヒアリングは「話を聞く」ためではなく、**gate を通すか戻すかの
> 判定データを取る**ために行う。したがって、事前に「どう答えられたら不合格か」を決めておく。
> それを決めずに始めたヒアリングは、必ず「手応えはあった」という結論になる。

## 0. 判定基準（先に確定させる）

### Product A（Credits）

| 条件 | 合格ライン |
|---|---|
| 「enforcement を自前実装済み or 実装を試みて諦めた」 | **10社中 6社以上** |
| 「赤字ユーザーの割合を即答できない」 | 10社中 8社以上 |
| margin 診断ツールに自社データを入れてもよいと答える | 10社中 5社以上 |

### Product B（Wallet）

| 条件 | 合格ライン |
|---|---|
| 「支出事故があった、または事故の恐怖で自律化を止めている」 | **10社中 6社以上** |
| エージェントがすでに何らかの支払い手段に触れている（ICP 判別条件） | 10社中 7社以上 |
| Agent Spend Policy Template をダウンロードし、社内で共有したと答える | 10社中 4社以上 |

### 不合格時の行動

Master Doc §6.1 のルールに従う。**説得力あるローンチ動画/ストーリーボードが明確に作れないなら
Concept 段階に戻す。** ヒアリング結果が合格ラインを割った場合、ピボットではなく差し戻し。

## 1. 原則

1. **未来ではなく過去を聞く。** 「使いますか?」ではなく「**先月**どうしましたか?」。
   意向は当てにならないが、すでに払ったコストは事実である。
2. **課題を説明しない。** こちらから「赤字ユーザーって問題ですよね」と言った瞬間、
   相手はそれに同意する。同意は情報ではない。
3. **価格は最後に、単独で聞く。** 前段でプロダクトを説明した後の価格反応は
   相手の礼儀に汚染される。§5 の方法で聞く。
4. **数字を必ず1つ持ち帰る。** 「けっこう大変です」で終わらせない。時間・金額・件数のどれかに落とす。
5. **録音より即時メモ。** §6 のテンプレを面談中に埋める。記憶からの再構成をしない。

## 2. Product A — Credits（30分）

### 2.1 対象選定

- 月次 $5k–100k MRR の AIアプリ。画像/動画生成、AIコンパニオン、writing、coding tool
- ソロ〜10名程度
- **除外**: エンタープライズ SaaS、シート課金のみで変動費が小さいもの

**探し方**: Product Hunt / X / Indie Hackers の公開 MRR、AI ディレクトリ、
既存 billing OSS リポジトリの issue 投稿者。

### 2.2 スクリプト

**A. 現状（8分）— 説明しない、聞くだけ**

1. 今の課金の形を教えてください。サブスクだけですか、クレジットもありますか?
2. クレジットがある場合 — **誰が、いつ、どうやって作りましたか?**
3. 残高が足りないユーザーが重い操作を叩いたとき、いま何が起きますか?
   - （追い）実行される? 途中で止まる? 実行してから請求される?
4. その挙動を実装するのに、どのくらいかかりましたか?
5. その後、そのコードを直したのは直近でいつですか? 何が理由でしたか?

> **判定ポイント**: 質問3で「実行してから引く」「マイナスになる」「実は防げていない」が出たら、
> それは *enforcement を諦めた* に該当する。質問4で「2週間以上」なら *自前実装済み* に該当。

**B. コスト（8分）**

6. 先月のモデル費用は、売上の何%でしたか?
7. ユーザー単位で粗利を見ていますか? 見ている場合、どこで見ていますか?
8. **粗利がマイナスのユーザーは何%いますか?**
   - （即答できない場合）それを知るには何をする必要がありますか? どのくらいかかりますか?
9. モデルの価格が変わったとき、自社の価格やクレジット換算をどう直しましたか?

> **判定ポイント**: 質問8への即答可否がそのまま wedge の検証。
> 「調べれば分かる」は「知らない」と同じ扱いにする。

**C. 解約(10分)**

10. 解約したユーザーは、直前の1週間どういう使い方をしていましたか?
11. 残高が切れたユーザーに対して、いま何かしていますか? それは自動ですか、手動ですか?
12. トップアップを買う人と買わない人の違いを、何かで説明できますか?
13. その施策が効いているかどうかを、どうやって判断していますか?

> **判定ポイント**: 質問13に対して「A/Bしている」と答える企業は少ないはず。
> ホールドアウト測定（PRD §10.4）が差別化になるかの検証。

**D. 課金基盤（2分）— Q-05 の検証**

14. 課金は Stripe ですか? モバイルアプリはありますか?
15. （モバイルがある場合）App Store / Play の課金はどう扱っていますか?

**E. クロージング（2分）**

16. 同じ問題で困っている人を1人紹介してもらえますか?
17. 赤字ユーザー% を出す無料ツールを作っています。自社データで試してもらえますか?

> 質問17の承諾率が、Product A の合格条件3。

## 3. Product B — Wallet（30分）

### 3.1 対象選定

- 従業員 50–1,000 名。エージェントを**本番で**動かしている
- **ICP 判別条件**: エージェントがすでに何らかの支払い手段に触れている、
  または触れさせようとして止まっている

**探し方**: agentic workflow の事例公開企業、AI プラットフォームチームの採用票、
Claude Code / Cowork の法人利用者、AI エージェント関連のカンファレンス登壇者。

### 3.2 スクリプト

**A. 現状（10分）**

1. 本番で動いているエージェントは何体くらいですか? 何をしていますか?
2. そのうち、お金を使うものはありますか? 何に使っていますか?
3. 使っているとしたら、**支払い手段は何ですか?**
   - （追い）誰名義のカードですか? API キーは誰のものですか?
4. 上限はどうやって設定していますか?
   - （追い）その上限は**実際に効きますか?** 超えたら止まりますか?
5. 先月、エージェントが使った金額を、エージェント別に出せますか?

> **判定ポイント**: 質問3で「個人のカード」「共有の法人カード」「プロバイダのコンソール上限だけ」
> が出たら、統制されていない。質問4で「プロンプトで指示している」が出たら、
> それは統制ではない（PRD §4.1-1）。

**B. 事故と恐怖（10分）— 合格条件の中核**

6. エージェントの支出で、想定外のことが起きたことはありますか?
   - （なければ）**やらせていないことはありますか? それはなぜですか?**
7. （事故があれば）何が起きて、いくらで、どう気づきましたか?
8. （なければ）自律的に払わせるのを止めているとしたら、何が解決すれば解禁できますか?
9. 「エージェントに会社のカードを渡す」ことについて、財務や経理は何と言っていますか?

> **判定ポイント**: 質問6–8 のどちらかで実害または明確な抑制が出れば合格条件に計上。
> 「特に何も」「まだそこまで考えていない」は ICP 外として除外し、10社に数えない
> （**除外した社数は必ず記録する**。除外が多いこと自体が「市場が早すぎる」という
> Master Doc §5 Product B risk 4 の証拠になる）。

**C. 統制と監査（8分）**

10. 支出の承認が要る場合、いまは誰がどうやって承認していますか?
11. 監査や締めのときに、エージェントの支出について何を聞かれますか?
12. 「この支払いは誰の判断か」を聞かれたら、いま答えられますか?
13. エージェントが侵害されたとして、支払いを止めるのに何分かかりますか?

**D. クロージング（2分）**

14. 「Agent Spend Policy Template」を作っています。社内で使えそうか見てもらえますか?
15. 同じことを考えている人を1人紹介してもらえますか?

## 4. 聞いてはいけない質問

| ❌ | なぜ | ✅ 代わりに |
|---|---|---|
| 「こういうプロダクトがあったら使いますか?」 | 意向は行動を予測しない | 「先月、同じ問題にどう対処しましたか?」 |
| 「赤字ユーザーって困りますよね?」 | 課題を教えている | 「粗利がマイナスのユーザーは何%ですか?」 |
| 「月 $99 なら払えますか?」 | 礼儀で肯定される | §5 |
| 「クレジット制と従量課金、どっちがいいですか?」 | 設計をユーザーに投げている | 「いまどちらですか? なぜそうしましたか?」 |
| 「AIエージェントの未来をどう見ますか?」 | 一般論に時間を溶かす | 聞かない |

## 5. 価格の聞き方（Q-04 の検証）

面談の最後、プロダクト説明の**後ではなく**、独立した話題として聞く。

1. 「いま、この領域に月いくら払っていますか?」（既存 billing、内製の人件費換算）
2. 「その内製を維持するのに、月何時間かかっていますか?」
3. → 時間 × 自社の時給換算 = **相手が自分で出した TCO**。これが価格の上限アンカー
4. その上で: 「月 $X で、それが不要になるとしたら、$X はいくらまでなら即決ですか?」

**%課金については別途聞く**: 「クレジット流通額の 1% という形だと、どう感じますか?」
Master Doc §3.3 の「%課金は TCO で嫌われる」が自社 ICP でも成立するかの検証。
嫌悪反応が 10社中 6社以上なら、%課金は主軸から外す。

## 6. 記録テンプレ（面談中に埋める）

```
社名 / 面談者 / 役割 / 日付:
プロダクト:  MRR レンジ:  従業員数:

■ ICP 判定
[ ] ICP に該当   [ ] ICP 外（理由:                     ）

■ Product A 合格条件
[ ] enforcement を自前実装済み（工数:      ）
[ ] enforcement を試みて諦めた（諦めた理由:            ）
[ ] どちらでもない
[ ] 赤字ユーザー% を即答できなかった
[ ] 診断ツールを試すと答えた

■ Product B 合格条件
[ ] 支出事故あり（内容:            / 金額:        / 発覚経路:        ）
[ ] 事故の恐怖で自律化を止めている（解禁条件:                  ）
[ ] どちらでもない
[ ] エージェントがすでに支払い手段に触れている

■ 持ち帰った数字（最低1つ）
                         

■ 想定外だったこと（1行）
                         

■ 相手が使った言葉（そのまま。LP のコピーに使う）
「                                          」

■ 次アクション / 紹介
```

> **「相手が使った言葉」欄を必ず埋める。** LP のコピーは自分の言葉ではなく、
> ICP が実際に使った言葉で書く。Master Doc §4.4 の voice はトーンの規定であって、
> 語彙の出所ではない。
